# Local API contract

All paths start `/api`. JSON errors: `{error:{code,message,details?}}`. IDs are opaque; timestamps are ISO UTC. Unknown request fields fail. Local single-user, same origin. No authentication/tenant claims.

`GET /bootstrap`: `{report_types:[], snapshots:[], assets:[], programs:[], jobs:[], historical_target_asset_ids:[], capabilities:{...}, demo:true}`. Lists may use full records (small local installation). Snapshot records are the shape in native-contract.md plus `digest`. Source assets: `{id,filename,digest,size,media_type,created_at,status:'usable'|'blocked',profile:{format,row_count,columns,sheets?,regions?,sample_rows?,image?,warnings:[],eligible_roles:[]},demo}`. Reserved assets instead return a redacted profile, `reserved:true` and an access reason. Programs: `{id,report_type_id,name,version,digest,state:'candidate'|'published'|'discarded',coverage:[{id,label,kind,status}],decisions:[{id,question,alternatives:[{value,label,consequence}],resolution}],learning?,evaluation:null|{passed,checks:[{name,passed,detail}],digest,basis_digest,created_at,holdout_count,reconstruction_count,image_fixture_digest?,image_render_digest?},limitations:[],input_contract,created_at}`. Report type: `{id,name,description,active_program_id,created_at,demo}`. Image capabilities are `{formats:['png','jpg','jpeg'],max_per_report:1,frozen_png_export:true}` under `capabilities.images`. `capabilities.learning` is `bounded_regional_policy_search`; `capabilities.model` exposes provider configuration and limits without credentials.

Program records created from a release add `lineage:{parent_program_id,parent_program_digest,reason}`. Their decisions retain `prior_resolution` and `inherited_from:{program_id,program_digest,resolved_at?}` as context, while current resolutions start unset. Discarded candidates add `discard:{reason,actor,at}`. Initial candidates have no lineage.

`GET /programs/{id}` and program entries in bootstrap add a derived read model: `active_program_id`, `runtime_status:'current'|'code_changed'|'restart_required'`, `lifecycle_status:'active'|'historical'|'candidate'|'discarded'`, and `change_summary:null|{added_files:[],changed_files:[],removed_files:[],python_changed,policy_changed,decision_review_required}`. These fields do not mutate historical release evidence. Mutation responses may contain the persisted program without these derived fields; refresh GET/bootstrap afterward.

- `POST /report-types {name,description?}` -> report type and candidate `{report_type,program}`. Current adapter is explicitly quarterly regional revenue; this is not arbitrary automated learning.
- `POST /assets` multipart `file` -> immutable inspected asset. Accepted CSV/XLSX/DOCX/PDF/PNG/JPG/JPEG; only supported tabular assets can bind `transactions`. Supported still images receive the `report_image` role. `GET /assets/{id}` returns inspection metadata; `GET /assets/{id}/download` returns original bytes. `GET /assets/{id}/preview` returns the verified normalized PNG for an image asset.
- `POST /report-types/{id}/examples {report_asset_id,source_asset_ids,period,corpus_role:'authoring'|'development'|'reserved',label?,caveats?}` -> immutable example. This profile requires exactly one distinct transaction source and one eligible DOCX/PDF target. Labels allow 100 characters, caveats 2,000. The server stores original identities and independent target observations; registering an example does not itself run learning.
- `GET /report-types/{id}/examples` -> examples for the type. `GET /examples/{id}` -> example detail, including `effective_role` and `exposed`; `inspection` is null while reserved.
- `POST /examples/{id}/reveal {reason}` -> example with effective role `development` and immutable exposure history. A reserved pair cannot remain an untouched holdout after disclosure. Reasons allow 1–1,000 characters.
- `GET /model-status` -> `{configured,provider:'openai',model,limits:{timeout_seconds,max_output_tokens,max_request_bytes,max_response_bytes}}`; no credential is returned.
- `POST /programs/{id}/learn {expected_digest,requirements?,engine:'deterministic'|'openai',idempotency_key}` -> 202 learning job. Requires an authoring example and at most twelve pairs in the corpus. Requirements allow 4,000 characters; engine defaults to deterministic. OpenAI assistance requires configured server credentials. The result is a candidate analysis with competing hypotheses, target-region coverage, assumptions and limitations. Model suggestions never resolve policy decisions or publish a program.
- `POST /programs/{id}/coverage {expected_digest,coverage_id,disposition:'out_of_scope',reason}` -> candidate with a new digest and invalidated evaluation. Only unresolved historical regions can be explicitly excluded; the caller cannot mark an unsupported region implemented or verified.
- `GET /programs/{id}` -> program with derived lifecycle, runtime and change information.
- `GET /programs/{id}/package` -> the published release's immutable source/package JSON download, verified against its artifact digest. Unpublished candidates have no package download.
- `POST /programs/{id}/candidates {expected_digest,reason}` -> 201, next candidate within the base program's report type. `reason` contains 1–1,000 characters after trimming. Captures installed code, resets evaluation/approval/current decision resolutions, and retains prior answers as context. Only one candidate may be open per type. Retrying the same base and reason reuses that candidate; a conflicting open candidate is a 409. Version allocation includes discarded candidates.
- `POST /programs/{id}/discard {expected_digest,reason}` -> discarded replacement candidate with an audit record. The same reason bounds apply. Published programs and the initial candidate of an unpublished type cannot be discarded. Historical records and the active release remain unchanged.
- `POST /programs/{id}/evaluate {expected_digest}` -> program with persisted independent checks. `POST /programs/{id}/decisions {decision_id,resolution,expected_digest}` -> program with a new digest (evaluation invalidated). `POST /programs/{id}/publish {expected_digest}` -> published program. Unresolved decisions, stale evaluation, changed active/base release, code drift, or a required server restart block publication. Publication atomically switches the active pointer only after both candidate and active-release preconditions pass.
- `POST /report-runs {report_type_id,asset_id,period,idempotency_key,image?}` -> job. Period fields: label,start,end_exclusive,comparison:{start,end_exclusive},timezone,as_of (ISO aware datetime). Optional `image` is `{asset_id,alt_text,decorative:false}`; it binds one inspected image separately from the transaction source. Omit it or send null for an image-free report. Descriptions are trimmed and limited to 500 characters; non-decorative images require a nonempty description. Decorative images may use an empty description. Extra fields, including client-supplied render hashes or dimensions, fail validation.
- `GET /jobs/{id}` -> `{id,kind:'generation'|'export'|'learning'|'composition',status:'queued'|'running'|'completed'|'blocked'|'failed'|'cancelled',stage,steps:[{stage,at}],result:{snapshot_id?|export_id?|program_id?},error:null|{code,message,details?},created_at,updated_at}`. `POST /jobs/{id}/cancel {}` persists cancellation. Poll until terminal; no fake progress percentages.
- `GET /report-snapshots/{id}` -> snapshot. `POST /report-snapshots/{id}/revisions {expected_revision,node_id,text,reason}` -> new snapshot (new ID and revision, old immutable). Only editable rich-text commentary may be changed; numeric literals outside fact references block, causal claims require review, and computed blocks cannot be edited.
- `POST /report-snapshots/{id}/compose {expected_revision,source_asset_ids?,objective,idempotency_key}` -> 202 composition job. Objective allows 1–1,000 characters; supply zero to five distinct qualitative sources. Historical target reports and reserved evidence are rejected by digest, including alias uploads. A successful job returns a new `review_required` snapshot with the same computed facts and captured commentary; acceptance remains a separate action. Missing model configuration or exhausted validation attempts produce a blocked job, never invented prose.
- `GET /report-snapshots/{id}/images/{node_id}` -> the exact frozen PNG bound to that image node, verified by digest and dimensions. A legacy image without a frozen derivative returns `IMAGE_UNAVAILABLE`; it is never resolved from newer asset metadata.
- `POST /report-snapshots/{id}/accept {expected_revision}` -> new accepted snapshot, audit record. Required blockers cannot be overridden through this endpoint. Human review acknowledgment is explicit.
- `POST /exports {snapshot_id,format:'docx'|'xlsx'|'pdf'|'pptx',policy:'compatible'|'strict',idempotency_key}` -> job. Compatible allows explicitly declared static representations. Strict XLSX blocks pending native pivot application certification. Draft exports are labelled drafts.
- `GET /exports?snapshot_id=...` -> array `{id,snapshot_id,format,filename,digest,status,manifest,created_at}`. `/exports/{id}/download` actual bytes; `/exports/{id}/manifest` JSON. `/report-snapshots/{id}/audit` downloads snapshot, source identities, validation and audit JSON (raw sources excluded).

## Image evidence and export

Image ingestion accepts still PNG/JPEG only, with a 20 MiB (20,971,520 byte) limit on both original and normalized files, at most 8,192 pixels per side and 16,000,000 total pixels. Animation, mismatched extension/decoded format, truncated bytes and invalid embedded color profiles are rejected. Inspection applies EXIF orientation, converts embedded color profiles to sRGB, preserves transparency and strips metadata into a frozen PNG.

The original upload remains downloadable under its original `digest`. `profile.image` describes the derivative with `width_px`, `height_px`, `render_digest`, `media_type:'image/png'`, `normalization:'exif_transpose_strip_metadata_png'` and color/original-dimension metadata documented in the native contract. The server verifies and pins these fields for the run; clients submit only the selected asset and its intended description/decorative status. A published program must declare `input_contract.optional_image` before accepting an image; older releases require the candidate upgrade workflow and otherwise return `IMAGE_PROGRAM_UNSUPPORTED`.

DOCX, XLSX, PDF and PPTX exports consume the frozen PNG without normalizing it again. The image participates in complete view coverage and export manifests, which retain original and render identities. Office files contain image objects; raster pixels are not editable diagram elements. PDF descriptions are visible and recorded in the manifest, but tagged-PDF accessibility is not certified. Native Excel pivot interaction certification remains pending. Image content is not OCR input or computed evidence; non-decorative images require review of the image and description.

Source upload is not report generation. Export never calls preparation. Run idempotency compares the original caller fields (report type, source asset, period and optional image selection/description/decorative flag); an identical retry returns its original job and release pin even after publication changes the active release. Changed image fields with the same key conflict. A new request key resolves the current active release. The bundled demo is labelled synthetic in records and output metadata.

After backend files change, restart the server to load them before creating/evaluating a replacement candidate. Archived program packages are retained for audit and restoration; they are not executed automatically. A queued job never adopts a newer release implicitly and can block when its pinned runtime is incompatible with installed code.

## Learning and evaluation evidence

An example stores `{id,report_type_id,label,caveats,report_asset_id,source_asset_ids,asset_digests,period,corpus_role,state,inspection,pair_digest,digest,created_at}` plus file names. Its inspection contains original asset identity, located observations, every inventoried target region and extraction issues. Regions are not silently removed when unsupported.

`program.learning` records `{engine,requirements,corpus_digest,corpus,example_ids,hypotheses,coverage,assumptions,limitations,created_at}` and optional model proposal/receipt. Each hypothesis has `{value,label,supported,checks}`; checks retain example IDs, expected/actual values, pass/fail and source locators. Coverage rows have `{id,example_id,region_id,locator,kind,text,component_id,status,reason}`. The three implemented values are `largest_absolute_change`, `largest_percentage_change` and `largest_current_revenue`. Resolving the `selection` decision updates the executable policy.

Historical evaluation compares the selected policy against independent observations, including displayed numeric rounding, table order/membership and the registered exact disclosure. Unresolved regions, contradictory expectations or absent observations fail their respective gates. A coverage exclusion records reduced historical scope; it does not override a failing numeric observation. The evaluation `basis_digest` covers candidate, corpus roles/exposure and reference fixture identities, and is checked again at publication. Corpus changes require learning again.

Reserved targets and paired sources are hidden from normal inspection/download, runtime binding and authoring by digest. Existing examples, snapshots and durable generation/composition requests prevent retroactive reservation of their source contents. `holdout_count` counts reserved pairs whose target details are withheld; their visible pass/fail gates and repeated evaluation must not be advertised as independent unseen-performance measurements. Reveal records exposure and changes the effective role to development.

Learning and composition use normal leased jobs and expected identities. Their final candidate/revision writes and job completion occur in one fenced transaction. A cancelled or superseded worker cannot commit its result, and composition cannot overwrite a newer report revision. Persisted model responses may be reused for an identical logical stage; remote execution during a crash window is not guaranteed exactly once.
